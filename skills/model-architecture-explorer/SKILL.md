# 模型架构交互可视化

把模型源码转成读者可以逐步展开的架构网页。图中的连接、执行顺序、张量形状和配置区别应能由当前工作区代码解释。使用用户的语言，沿用已有页面的设计与技术栈；新建且无特别要求时，优先离线可用的 HTML + SVG + JavaScript。

## 从代码建立结构

- 先检查工作区说明与未提交修改。找到模型构建入口、`forward`、配置 dataclass / YAML、训练与推理适配层，再沿真实调用链读取各组件。README 和论文用于背景，当前源码用于确认实现。
- 梳理输入预处理、编码、特征投影、位置编码、交互 / 融合、状态或条件注入、解码、输出变换。区分模型内操作与模型外归一化、采样和 rollout；不要把一个模型的阶段强加给另一个模型。
- 分别核对库默认值、训练配方、checkpoint 覆盖值；说明页面实际展示哪一种。配置切换应联动形状、实例名称、层数和算子说明，不只改变标题。
- 推导关键形状，写明符号和 padding / patch / horizon 等假设。编码特征宽度、attention 内部宽度、head 数与 head dim 可能不同。检查残差的真实底座、Pre-/Post-Norm、softmax 维度、mask、共享参数与独立层参数。
- 不必加载大模型权重来解释代码。没有执行推理时，将形状标为推导结果；动画只表示信息依赖，不代表实际耗时或 GPU 调度。

## 设计真正的逐层展开

按模型复杂度选择视图数量：整体图说明主要数据依赖；细图展开关键模块；算子详情提供计算说明、输入输出形状、配置 / 层实例与源码入口。

交互契约应直接可见：

- 整体图中标为“点击展开”的模块，单击就进入对应内部计算图；提供返回与清晰的当前视图标记。
- 细图中的可点击算子，单击打开明显的详情弹窗或内联展开区。仅悄悄更新右侧检查器，不足以兑现“展开”。检查器可以辅助展示，并提供显式展开按钮。
- 同结构的多层可使用层号选择器，但要说明结构相同、参数是否独立，并更新实例路径。中间解码层的输入是上一层特征，不能始终画成原始查询直接输入每一层。
- 长图需要可读的文字、内部滚动或放大方式。键盘可激活模块、关闭弹窗；移动端不要让整个页面横向溢出。

## 制作网页与源码映射

新建页面时可复制 [assets/explorer.html](assets/explorer.html)，按 [references/page-spec.md](references/page-spec.md) 填写模型 spec，然后使用标准库构建工具：

```bash
python <skill-dir>/scripts/build_explorer.py \
  --repo /absolute/model/repo \
  --spec /absolute/model/repo/visualization/architecture/spec.json \
  --output /absolute/model/repo/visualization/architecture/index.html
```

模板是可适配的起点，允许根据既有项目调整样式、布局和交互。若修改模板，放到目标项目中并通过 `--template` 指定；不要为单个仓库修改已安装 skill 的共享模板。

构建器会检查视图 / 模块引用和布局边界，只读取 spec 明确引用的源码文件，用 Python AST 提取定义的真实行号，再将 spec 和源码快照嵌入一个 HTML。它不会自动发现模型结构，也不会证明图中数学关系正确；这些判断必须通过读代码完成。

- 为主要阶段建立 `文件 + 类/方法` 映射，显示原始行号。链接到可阅读的源码快照，避免依赖浏览器打开服务器绝对文件路径。
- 选用离线快照时，嵌入 JSON 中的 `<` 要转义，避免源码中的 `</script>` 截断页面。不要嵌入权重、数据集或无关仓库内容。
- 明确 SVG 的 `viewBox`、导出宽高与背景；长图导出不能沿用整体图的小尺寸。模型源码或配方改变后，重新核对 spec，再重建；刷新快照不会自动修正图形。

已有网页可直接按以上契约改造，不必迁移到模板。优先新增可审阅的可视化文件，保持模型训练 / 推理代码不受影响。

## 验证用户实际操作

使用可用的浏览器工具；本地安装了 Playwright 时也可用它。围绕真实行为验证：

1. 通过用户将访问的 HTTP 地址加载页面；离线作为交付目标时也检查 `file://`。确认渲染后的图和控制台，而非只检查 HTML 文件存在。
2. 实际点击“整体模块 → 内部细图 → 算子详情 → 对应源码”，检查视图确实变化、弹窗可见、正确符号与行号被显示；测试关闭 / 返回，不能只断言右侧文字变了。
3. 检查配置和层号切换后的实例、形状、残差策略。核对 SVG 标签没有超出图框、主要文字不溢出算子框，以及导出文件尺寸。
4. 按页面功能检查键盘、移动端与相关控制。只验证任务实际提供的功能；不必为纯文档网页运行模型训练测试。

模板生成的页面可直接运行附带的可选 Playwright 检查器（已有自定义页面的 DOM 不一定适用）：

```bash
python <skill-dir>/scripts/check_explorer.py --page /absolute/path/index.html
python <skill-dir>/scripts/check_explorer.py --url http://127.0.0.1:8765/ --screenshot /absolute/path/preview.png
```

它验证每个配置、节点的实际下钻或弹窗、返回、源码范围、导出尺寸、文字边界、键盘激活与移动端点击。它不判断模型的数学语义，也不覆盖项目后来新增的专用控件；这些需要按上述要点另行验证。

浏览器验证不可用时，完成静态检查并明确未验证的部分；不要声称交互已通过。用户反馈“和之前一样”时，先区分旧页面、编辑器打开文件、模块没有展开等情况，复现真实点击；必要时对比服务返回内容与文件摘要，不能默认归因为缓存。

## 交付与访问

说明页面位置、最有价值的展开路径、已验证项，以及任何推导假设。远程服务器上的 `localhost` 属于服务器；若用户需要访问指导，按其连接方式给出端口转发或下载单文件的方法，不把远程绝对文件链接说成一定能在本机浏览器打开。

若启动本地预览服务，先确认端口 / 服务目录，使用任务环境已有的服务管理方式，不中断无关进程。交付时可保存一张实测点击效果图，帮助读者确认界面状态。不要把 TurboVLA 的层数、维度、动作头或目录当成其他模型的默认值。
