# 架构探索器的阅读与视觉质量

用于设计完整新页面、改造既有页面或对照用户给出的参考页面。先看参考的真实渲染和交互，再决定哪些结构应保留；不能只从 HTML 是否存在、按钮是否能点来判断成品质量。

## 先建立阅读层次

- **模型概览**：模型名称、用一句话说明的核心思路、实际配置的关键参数。参数卡优先显示输入规模、特征宽度、交互深度、输出空间等对理解有用的信息。不要把源码文件数等工具统计冒充模型参数。
- **架构工作区**：整体图是主要阅读入口。分组、颜色、分支与连线说明数据依赖；旁边的检查器补充选中模块的说明、形状、参数和源码。图和检查器应有清晰的视觉主次。
- **深入解释**：核心机制的 LaTeX 公式、容易误读的实现要点、按前向路径排列的张量形状表。它们解释图为什么这样画，而不是重复模块标题。
- **逐层查看**：整体模块进入内部计算图，算子进入详情，详情进入源码。相同层的实例选择、已有的形状参数和演示功能应保留，并核对其联动行为。

按模型和用户任务调整内容，不必硬凑卡片数。已有高质量页面时优先局部修改；不要为了适配标准 spec 而删掉有用的阅读区、层选择器、控制项或特有布局。

## 图的密度与排版

- 先按输入、编码、交互、解码等真实阶段组织布局，再为每个节点安排位置。关键分支、残差与条件注入应能沿线追踪，避免把所有模块排成相同大小的长列表。
- 大模块可使用 `blocks` / `badge` / `foot` 展示内部摘要与重复次数；下钻后再解释完整算子。连线不要穿过节点，旁路要有足够间距。
- 总览节点只放名称、关键配置和关键形状。详细的公式、说明和源码放入细图或详情；适合直接解释计算关系的图内公式可以使用 LaTeX，并为实际渲染高度预留空间。
- 不把整张长图一味缩小到屏幕里。保持可读字号，使用内部滚动、缩放和有意义的视图拆分。手机上不让页面整体横向溢出。
- 颜色稳定对应数据流或计算阶段；浅背景、边框与留白辅助分组，不用装饰替代结构。

## 形状与前向演示

模板支持 `stats`、`mechanism`、`notes`、`trace`、`controls`、`dimensions` 和视图 `flow`，格式见 [page-spec.md](page-spec.md)。

- 只有在已核对的关系确实会随参数变化时才提供控制项。改变 batch、序列长度或模型配置后，参数卡、图内形状、检查器、机制说明与张量表应保持一致。
- `flow` 显式声明前向步骤；并行或逻辑上同阶段的模块可以共同高亮。不能根据图上从左到右的位置自动推断真实执行顺序。
- 前向演示只说明信息依赖，不表示计算耗时、设备调度或实际执行了模型。

## 用同一组内容验证

1. 比较用户参考与结果时，尽量使用同一个模型、配置和数据密度。一个只有一两个节点的示意 spec 不能证明复杂模型的页面质量。
2. 实际查看桌面总览、内部计算图、算子详情和手机布局的截图。检查文字是否被裁切、图是否过小、长公式是否遮挡相邻算子、侧栏是否挤压主图，以及下方说明是否仍然完整。
3. 检查配置、形状参数、层实例和演示的联动。验证导出的 SVG 在单独打开时仍保留图内公式、字体与正确尺寸。
4. 检查脚本通过后仍需看截图。自动检查能发现交互和边界错误，不能代替对信息组织、视觉层次与解释质量的判断。

参考页的模型参数和源码属于那个模型；只复用设计原则，不把其专用数据写进通用模板。
